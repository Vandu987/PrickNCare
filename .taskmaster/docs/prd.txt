# PricknCare — Phlebotomist Blood Sample Collection Platform
# Product Requirements Document (PRD)
# Version: 1.0 | Date: February 2026
# Prepared By: Epik Technocravers Private Limited

## 1. Executive Summary

Build a PAN India Phlebotomist Blood Sample Collection Platform that enables diagnostic labs and healthcare providers to manage home blood collection services efficiently. The platform consists of a web-based admin panel, client portal, and mobile application for field phlebotomists.

## 2. Project Objectives

- Build a scalable platform for managing home blood sample collection across India
- Enable clients (labs/hospitals) to place collection requests via web portal
- Provide mobile app for phlebotomists to manage daily collections
- Centralized admin panel for operations management
- Real-time tracking and status updates
- Automated assignment and route optimization
- Multi-tier pricing based on collection type and priority

#### 4.2.5 Order Management

**Order Lifecycle:**
New Order → Pending Assignment → Assigned → Accepted → In Transit → Collected → Sample Handed Over → Completed

**Order Statuses:**

| Status | Description |
|--------|-------------|
| Pending | Awaiting assignment |
| Assigned | Phlebo assigned, notification sent |
| Accepted | Phlebo accepted the order |
| Re-routed | Reassigned to another phlebo |
| In Transit | Phlebo on the way |
| Collected | Sample collected successfully |
| Uncollected | Collection failed (patient not home, etc.) |
| Cancelled | Order cancelled |
| NSA | No Service Area |

**Assignment Features:**
- Manual assignment to specific phlebotomist
- Auto-assignment based on zone/pincode matching
- Bulk assignment of multiple orders
- Re-routing to another phlebotomist
- Priority flagging for urgent orders

#### 4.2.9 Sample Accessioning (Lab Receiving)

When samples arrive at the lab, this module allows verification and acceptance.

| Field | Description |
|-------|-------------|
| Order ID | Unique order identifier |
| Patient Name | Patient name from order |
| Sample Type (Vial) | EDTA (Purple), SST (Yellow), Fluoride (Grey), Urine Container |
| Quantity | Number of vials/containers |
| Integrity | OK, Lipemic, Leaked, Hemolyzed, Clotted, Insufficient |
| Status | Accepted, Hold, Rejected |
| Rejection Reason | If rejected - reason selection |
| Received By | Lab technician name |
| Received Time | Timestamp |

**Integrity Checks:**
- OK — Sample accepted for processing
- Lipemic — Fatty sample, may affect results (Hold)
- Leaked — Sample damaged, rejected
- Hemolyzed — Red cell damage, may need recollection
- Clotted — Blood clotted in anticoagulant tube
- Insufficient — Not enough sample volume

**Workflow:**
Phlebo hands over samples → Lab scans barcode → Verify integrity → Accept/Hold/Reject → Update status in system → Notify client if rejected


#### 4.2.10 Phlebotomist Cash Reconciliation

Daily settlement of cash collected by phlebotomists.

| Field | Description |
|-------|-------------|
| Phlebo Name | Phlebotomist name |
| Total Appointments | Number of collections done |
| Cash Collected | Total cash received from patients |
| Online/UPI | Total digital payments collected |
| Total Collection | Cash + Online amount |
| Handed Over | Yes / Partial / No |
| Discrepancy | Difference with notes (Fuel, Shortage, etc.) |

**Reconciliation Workflow:**
End of day → Phlebo submits cash → Admin verifies amount → Record discrepancies (fuel allowance, shortages) → Mark as Handed Over → Generate daily settlement report

**Discrepancy Types:**
- Fuel allowance deduction
- Cash shortage
- Overage
- Patient refund
- Incentive adjustment

**Reports:**
- Daily collection summary by phlebo
- Weekly/monthly settlement reports
- Discrepancy tracking
- Outstanding dues

5. Verify patient (OTP/ID)
6. Collect sample
7. Capture photo proof of samples
8. Get patient digital signature
9. Collect payment (Cash/UPI)
10. Generate receipt
11. Mark as Collected
12. Hand over samples at lab

## 6. Security & Compliance

- HTTPS/SSL encryption on all endpoints
- Role-based access control (RBAC) with granular permissions
- Data encryption at rest (AES-256) and in transit (TLS 1.3)
- HIPAA-aware data handling for patient information
- Audit logs for all user actions (who did what, when)
- GDPR-compliant data management
- Secure OTP verification with rate limiting
- Session management with auto-timeout
- API rate limiting and throttling
- Input validation and SQL injection prevention
